Stored clobber disables the sanitizer

This app lets you save a profile bio. The bio is sanitized on save (scripts and event handlers are stripped, but harmless tags survive) and then re-rendered on every page load — a classic stored HTML injection. A second, unsanitized-by-default comment widget reads its configuration from a global. Chain the two.

Goal: make the comment render as raw HTML and execute window.__pwned = true via an onerror handler.

Victim code

// 1. stored bio is re-rendered first (sanitized on save)
victim.innerHTML = sessionStorage.bio;

// 2. read security config from a global
const SECURITY = window.securityConfig
               || { strict: true };

// 3. render the comment
comments.innerHTML = SECURITY.strict
  ? escapeHtml(comment)
  : comment;      // raw HTML when not strict

SECURITY.strict is read fresh on every render, and the bio element is in the DOM before that read. Element properties that don't exist are undefined — which is falsy.

Step 1 — profile bio (sanitized on save)

Step 2 — comment (escaped unless clobbered)

Hint 1

What HTML can you put in the bio that the sanitizer keeps, and that creates a global named securityConfig?

Hint 2

A bare <a id="securityConfig"> is enough: the anchor becomes window.securityConfig, and .strict on an anchor is undefined, not true.

Solution

Bio (step 1):

<a id="securityConfig"></a>

Comment (step 2):

<img src=x onerror="window.__pwned = true">

On the next render the bio is inserted first, window.securityConfig.strict is undefined, so the comment is assigned to innerHTML verbatim and the broken image fires onerror.
