DOM Clobbering Lab

DOM clobbering is an HTML-only attack: elements with id or name attributes become properties of window and document, letting an attacker overwrite values that JavaScript reads later. No script injection required. Each lab below is a small, self-contained "victim app" that you can feed HTML.

How this works

Type HTML into the payload box on a lab page. It is rendered into the victim's page (#victim), then the victim's JavaScript runs against it. If you make the app misbehave — leak its secret, redirect a request, or execute your code — press Verify exploit to capture the flag.

Anything you exfiltrate shows up in the Attacker inbox (a real collector endpoint on this server at /collect).

Challenges

LAB 1 · easy
Debug mode by default
A global flag decides whether the app runs in debug mode. You have no script execution — only HTML.
LAB 2 · easy
Analytics beacon
The app builds a beacon URL from a config object. Steal the session id.
LAB 3 · medium
Checkout hijack
A form's submission target is resolved from the DOM. Reroute a customer's order.
LAB 4 · hard
Stored clobber disables the sanitizer
A persisted profile field survives sanitization. Turn that into XSS on a comment.
LAB 5 · hard
Capstone: unsigned upload
Two independent clobbers: skip the signature check and move the upload destination.

Rules

  • No <script> tags and no editing the victim code — the point is HTML-only clobbering.
  • Payloads are per-run; use Reset page to start clean (Lab 4 stores state in this tab).
  • Everything runs locally on 127.0.0.1. Do not deploy this to a public host.
